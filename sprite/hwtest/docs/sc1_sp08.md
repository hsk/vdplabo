# SCREEN 1 で大量のスプライトを飛び回らせる

このサンプルは、これまでのテストプログラムとは異なり、スプライトを大量に表示するデモプログラムです。

ソースコード: [sc1_sp08.asm](../sprite1/sc1_sp08.asm)

元々は Python で作成していたスプライトデモをアセンブラへ移植したもので、32 個のスプライトが画面内を跳ね回ります。

---

## このサンプルの目的

これまでのサンプルでは、

- スプライト表示
- キー入力
- 衝突判定
- スプライトオーバー
- タイトルアニメーション

などを個別に確認してきました。

このサンプルでは、多数のスプライトをリアルタイムに動かしながら VRAM 更新の実験を行っています。

---

## スプライトの構成

画面上には 32 個のスプライトが表示されます。

スプライトごとに次の情報を保持しています。

| オフセット | 内容 |
|------------|------|
| +0 | X速度上位 |
| +1 | X速度下位 |
| +2 | Y速度上位 |
| +3 | Y速度下位 |
| +4 | X座標下位 |
| +5 | Y座標下位 |
| +6 | Y座標上位 |
| +7 | X座標上位 |
| +8 | パターン番号 |
| +9 | 色 |

1 スプライトにつき 10 バイト使用しています。

---

## 固定小数点による移動

座標は整数ではなく 16 ビット値で管理されています。

```text
座標 = 上位8ビット + 下位8ビット
```

そのため 1 ピクセル未満の速度も扱えます。

速度も同様に 16 ビット値で保持しています。

```text
X += DX
Y += DY
```

という形で毎フレーム更新しています。

---

## ランダムな初速度

初期化時に各スプライトへランダムな速度を設定します。

```asm
call random
```

乱数の符号によって移動方向を決定しています。

```text
← → ↑ ↓
```

だけでなく、斜め方向へも移動します。

そのためスプライトごとに異なる軌道になります。

---

## 壁で反射する

スプライトが画面端へ到達すると速度を反転します。

```asm
HL = -DE
```

を計算し、

```text
DX = -DX
DY = -DY
```

として跳ね返しています。

この処理によりボールが壁で反射するような動きになります。

---

## 8x8 と 16x16 のパターン

サンプルには複数のスプライトパターンが登録されています。

最初に 8x8 パターンを VRAM へ転送し、その後 16x16 パターンを展開して登録しています。

```asm
sprite_pattern_data1
sprite_pattern_data2
```

スプライトごとに異なるパターン番号を割り当てているため、見た目に変化があります。

---

## update_vram の役割

内部データは 10 バイト構造ですが、VDP が必要とするスプライト属性は 4 バイトです。

| VDP属性 | 内容 |
|----------|------|
| Y | Y座標 |
| X | X座標 |
| パターン | パターン番号 |
| 色 | 色番号 |

そのため `update_vram` 関数で必要な情報だけを抜き出して VRAM の属性テーブルへ転送しています。

```asm
call update_vram
```

この部分は Python 版でいう描画処理に相当します。

### なぜ update_vram が必要なのか

ゲーム内部ではスプライトごとに次の情報を保持しています。

- 16ビットの X 座標
- 16ビットの Y 座標
- 16ビットの X 速度
- 16ビットの Y 速度
- パターン番号
- 色番号

しかし VDP のスプライト属性テーブルは次の 4 バイトしか持てません。

| 属性 | 内容 |
|------|------|
| 1バイト目 | Y座標 |
| 2バイト目 | X座標 |
| 3バイト目 | パターン番号 |
| 4バイト目 | 色番号 |

そのため内部データをそのまま `SPRATR` に転送することはできません。

`update_vram` では、10 バイト構造のスプライト情報から

- Y座標上位バイト
- X座標上位バイト
- パターン番号
- 色番号

だけを VRAM のスプライト属性テーブルへ転送しています。

厳密にはデータ変換を行っているわけではありません。

内部データは次のような並びになっています。

```text
DXH DXL DYH DYL XL YL YH XH PAT COL
```

VDP が必要なのは後半の

```text
YH XH PAT COL
```

だけです。

そのため `update_vram` は各スプライトの先頭 6 バイトを読み飛ばし、必要な 4 バイトだけを VRAM へ転送しています。

```text
内部形式(10バイト)
[DXH DXL DYH DYL XL YL] YH XH PAT COL
           ↑ 読み飛ばす

update_vram

YH XH PAT COL
        ↓
SPRATR
```

この処理によって、ゲーム側は座標や速度を含む管理しやすい構造を維持したまま、VDP が必要とする属性だけを効率よく転送できます。

## 実行結果

画面上には多数のスプライトが表示されます。

```text
○   ◆   ○

   ◆   ○

○      ◆
```

それぞれが独立した速度で移動し、画面端で反射します。

しばらく眺めているだけでも動きの変化を楽しめるデモになっています。

## Python 版との関係

このプログラムは Python で作成していたスプライトデモをアセンブラへ移植したものです。

概念的には次のような処理を行っています。

```python
for sprite in sprites:
    sprite.x += sprite.dx
    sprite.y += sprite.dy

    if sprite.x < 0 or sprite.x >= WIDTH:
        sprite.dx = -sprite.dx

    if sprite.y < 0 or sprite.y >= HEIGHT:
        sprite.dy = -sprite.dy
```

アセンブラ版では同じ処理を固定小数点演算で実装しています。

- 多数のスプライトを管理する方法
- 固定小数点による座標と速度管理
- ランダムな初速度の生成
- 画面端での反射処理
- RAM 上の独自データ構造から VRAM 属性テーブルを生成する方法

テストプログラムというより、スプライトシステムの性能確認やデモ表示に近いサンプルになっています。
