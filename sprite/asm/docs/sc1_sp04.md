# SCREEN 1 でスプライトの衝突判定を行う

このサンプルは `sc1_sp03` の発展版です。

ソースコード: [sc1_sp04.asm](../sprite1/sc1_sp04.asm)

前回はカーソルキーでスプライトを移動しました。
このサンプルでは、移動するスプライトと固定スプライトの衝突判定を行います。

---

## このサンプルでの変更点

`sc1_sp03` から追加された機能は次の 2 つです。

- スプライト衝突判定
- 衝突時の色変更

プレイヤースプライトが中央のスプライトに重なると、色が変化します。

---

## プレイヤー情報を RAM に保持する

プレイヤー用に 3 バイトの領域を使用しています。

```asm
player_x equ 0C000h
```

| オフセット | 内容           |
|------------|----------------|
| +0         | X座標          |
| +1         | パターン番号   |
| +2         | 色番号         |

初期化時に設定しています。

```asm
ld hl, player_x
ld (hl), 100
inc hl
ld (hl), 0
inc hl
ld (hl), 15
```

---

## スプライト属性をまとめて更新する

前回は X 座標だけを書き換えていました。

```asm
ld de, SPRATR + 1
ld hl, player_x
ld bc, 3
call LDIRVM
```

今回は X座標、パターン番号、色番号の 3 バイトを一括で VRAM に転送しています。

これにより RAM 上の色番号を書き換えるだけでスプライトの色を変更できます。

---

## 衝突判定

MSX VDP はスプライト同士が重なるとステータスレジスタに衝突フラグをセットします。

BIOS はその値を `STATFL` に保存しています。

```asm
ld a,(STATFL)
and 00100000b
```

ビット5がセットされている場合、スプライト同士が衝突しています。

```asm
jr nz, collision
```

衝突している場合は `collision` ラベルへ分岐します。

---

## なぜ RDVDP を使っていないのか

本来の衝突フラグは VDP のステータスレジスタ0に存在します。

このサンプルでは BIOS が更新する `STATFL` を利用しているため、
VDP を直接読む必要はありません。

そのためソース中では `RDVDP` が定義されていますが、実際の衝突判定には使用していません。

```asm
ld a,(STATFL)
and 00100000b
```

BIOS が保持している状態を参照するだけで、スプライトの衝突を判定できます。

---

## 色変更処理

衝突していない場合は白色を設定します。

```asm
ld hl, player_x + 2
ld (hl), 15
```

衝突している場合は黄色に変更します。

```asm
collision:
    ld hl, player_x + 2
    ld (hl), 6
```

色番号を書き換えるだけで表示色が変化します。

---

## 実行結果

通常時:

```text
○      ○
```

衝突時:

```text
◎
```

プレイヤースプライトを移動して中央のスプライトに重ねると色が変化します。
