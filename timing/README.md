# エミュレーションにおけるタイミング

エミュレータでは、「どの単位で時間を進めるか」によって、実装の複雑さや再現精度が大きく変わります。

一般的には、粗い単位ほど実装は簡単で高速ですが、細かい単位ほど実機に近い再現が可能になります。

## 1. フレーム単位エミュレーション

最も簡単な方式です。

1フレームごとに:

- 入力を取得
- CPUを一定時間実行
- 画面を描画
- 音声を生成

という処理をまとめて行います。

実装しやすく高速ですが、画面途中で状態が変化するような表現は再現できません。

### 特徴

- 実装が簡単
- 高速
- 初期実装向け

### 苦手なもの

- ラスタスクロール
- 画面途中のパレット変更
- 正確な割り込みタイミング

## 2. ラスタ単位エミュレーション

画面を1ライン（ラスタ）ごとに処理する方式です。

例えば VDP が1ライン描画するごとに:

- CPUを少し実行
- 割り込み判定
- スクロール値変更
- スプライト判定

などを行います。

MSX やファミコンなどのラスタ演出を再現するためには重要になります。

### 再現しやすくなるもの

- ラスタスクロール
- ライン単位のパレット変更
- ライン単位の画面モード変更
- ラスタ割り込み

### 特徴

- フレーム単位より高精度
- 実機らしい画面演出を再現しやすい

## 3. CPU命令単位エミュレーション

CPU命令を1つ実行するごとに、他のデバイスとの同期を行う方式です。

例えば:

- CPU命令1個実行
- 実行クロック数を加算
- VDPやPSGを進める
- 割り込み判定

のように処理します。

多くのエミュレータで採用される、バランスの良い方式です。

### 再現しやすくなるもの

- I/O待ち
- 割り込みタイミング
- ポーリング処理
- デバイス同期

### 特徴

- 精度と速度のバランスが良い
- 一般的なゲーム機やPCエミュレータでよく使われる

## 4. クロック単位エミュレーション

1クロックごとに全デバイスを進める方式です。

CPU、VDP、DMA、メモリなどを、実機と同じクロック単位で同期させます。

非常に高精度ですが、処理量は大きく増えます。

### 再現しやすくなるもの

- wait state
- バス競合
- メモリアクセスタイミング
- VDPアクセス競合
- サイクル精度の動作

### 特徴

- 非常に高精度
- 実機に近い再現が可能
- 処理負荷が高い

## 5. スケジューラを用いたエミュレーション

イベント駆動型の方式です。

各デバイスが:

- 「次にいつ動くか」
- 「次のイベントはいつか」

を予約しながら進めます。

例えば:

- CPU割り込み
- VBlank
- タイマー
- DMA完了

などをイベントとして管理します。

高精度と高速化を両立しやすいため、高性能なエミュレータでよく使われます。

### 特徴

- 必要なタイミングだけ処理できる
- 高速化しやすい
- 実装は複雑

## 6. HDLシミュレーション

Verilator などを使い、HDL（Verilog/VHDL）そのものを動かす方式です。

これは一般的なソフトウェアエミュレーションというより、ハードウェアシミュレーションに近いものです。

FPGAやASICの検証でよく利用されます。

### 特徴

- ハードウェア記述を直接実行できる
- 非常に高精度
- 処理速度は遅いことが多い

## ハイブリッド方式

実際のエミュレータでは、すべてを同じ粒度で動かすとは限りません。

例えば:

- CPUは命令単位
- VDPはラスタ単位
- 音源はサンプル単位

のように、デバイスごとに異なる粒度を組み合わせることが多くあります。

## まとめ

一般的には:

| 方式         | 精度   | 速度 | 実装難易度 |
| ------------ | ------ | ---- | ---------- |
| フレーム単位 | 低     | 高   | 低         |
| ラスタ単位   | 中     | 高   | 中         |
| 命令単位     | 中〜高 | 中   | 中         |
| クロック単位 | 高     | 低   | 高         |
| スケジューラ | 高     | 高   | 高         |

となります。

エミュレータでは、必要な再現精度と処理速度のバランスを考えながら、どの粒度で時間を進めるかを選択することが重要になります。
