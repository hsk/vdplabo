拡張モード選択レジスタ

　互換性を重視していますので、デフォルトでは V9958互換モードになっています。新機能を使うには、拡張モード選択レジスタに所定の値を書き込む必要があります。

　拡張モードレジスタは、R#20 になります。00h を書き込むとV9958互換です。

| REGNO | bit7 | bit6 | bit5 | bit4 | bit3 | bit2 | bit1 | bit0 |
| ----- | ---- | ---- | ---- | ---- | ---- | ---- | ---- | ---- |
| R#20  | S16  | EVR  | ECOM | EPAL | SP3  | ILNS | SVNS | HS   |

- SP3 は、Sprite mode3 レジスタです。1を書き込むと、Sprite pattern generator table に、4bit/pixel のビットマップがある想定で、dot by dot で色づけされるスプライト表示になります。EPAL=1 必須です。

## はじめに

　今回は、V9968 の目玉機能の一つ「Sprite mode3」について説明します。

## 使える画面モード

　V9938/V9958 の Sprite mode は、画面モードに紐付いて連動して決まってしまいますが、V9968 の Sprite mode3 は、既存の Sprite mode1 または 2 を Sprite mode3 に切り替えることで使えるようになります。つまり、SCREEN1～12 で使う事が出来ます。
## 64枚表示・水平最大16枚

　Sprite mode3 では、スプライトプレーンは64枚あります。また、水平に最大16枚並べることが出来ます。

## Dot by dot の色つけ

　色は、ドット単位で 15色＋透明を指定できます。
　パターンジェネレーターテーブルは、SCREEN5 の背景画像と同じフォーマットで VRAM上に存在しています。Sprite mode2 の、複数重ねて OR して色を作る、という難解な仕様から解放されます。
## 16 Palette Set

　15色 + 透明 を、Palette Set と呼び、これが 16通り存在します。
　スプライトプレーン単位で、どの Palette Set を使って表示するか選択することが出来ます。同じパターンジェネレータの番号を指定していたとしても、異なる Palette Set を指定すれば、同じデザインの違う色で表示されるわけです。
　256色のパレットがありますが、この先頭 16色が Palette Set#0、次の 16色が Palette Set#1・・・最後の 16色が Palette Set#15 となります。その中に Palette#0～#15 のパレットがあるわけですが、Palette#0 の色は使われず、常に透明扱いになります。
　背景のパレットと共通であるため、下記のようになるので注意が必要です。

    SCREEN6 は PaletteSet#0 の Palette#0～#3 が背景に使われる

    SCREEN5, 7 及び 10, 11 のパレット部分は PaletteSet#0 が背景に使われる

    SCREEN8 では、PaletteSet#0～#15 全てが背景に使われる

## 透明度指定

スプライトプレーン毎に4段階の透明度を指定することが出来ます。
画像
4枚のスプライトで透明度を変えた表示

透明度 0% (不透明)、25%、50%、75% から指定できます。
ただし、透明度を無視した状態で、スプライトの優先順位に基づいて表示するスプライトが確定し、その確定したスプライトと背景画像とが合成される動作になりますのでご注意ください。
## サイズ指定

　スプライトプレーンのサイズは、16x16, 16x32, 16x64, 16x128 の4パターンから選択できます。幅が 16ドット固定ですが、これは残念ながらV9968の構造上増やせませんでした。
　ただ、16x128 のスプライトを使うと、拡大しなくてもスプライトで画面全体を覆うことが出来ますので、工夫次第で豊かな表現が可能になります。
## アトリビュート

　スプライトアトリビュートテーブルに書き込まれる内容は、1スプライトプレーンあたり 8byte に倍増しています。
画像
スプライトアトリビュートテーブルの1プレーン分の構造

Y9～Y0 はY座標、X9～X0 はX座標です。符号付きの値で -512～511 の範囲で指定します。
SZ1～0は、サイズ指定です。
MGYは垂直サイズ、MGXは水平サイズです。SZに何を指定していても、(MGXドット x MGYドット) のサイズで表示されるのでご注意ください。
MGX, MGY ともに 0 を指定すると 256 の扱いになります。
TP1～0 は、透明度です。
RVY は、上下反転フラグです。
RVX は、左右反転フラグです。
PS3～0 は、Palette Set番号です。
PTS2～0 は、後述する Pattern Set番号です。
PY3～0 は、Pattern Set内のパーツ番号（垂直位置）です。
PX3～0 は、Pattern Set内のパーツ番号（水平位置）です。
## パターンジェネレータの番号指定

VRAM256KB ありますが、これを SCREEN5 と同じイメージで8ページに分けます。背景と区別するために、ページではなく Pattern Set と呼びます。
画像
8つの Pattern Set と、その中の位置指定

1つの Pattern Set は、256ドット x 256ドットの領域を持っています。1ドット 4bit です。
これを、16ドット x 16ドットのパターンが、水平16個、垂直16個並んでいると見なします。この水平16個のどれを使うか指定するのが PX3～0 の 4bit、垂直16個のどれを使うか指定するのが PY3～0 の 4bit となります。
SZ に 0 を指定した場合は 16ドット x 16ドットのスプライトなので、これが一対一に対応するわけですね。
では、SZ=1 だった場合はどうなるのかというと、(PX,PY) で指定した位置から、SZで指定した数だけ垂直に並んでいるパーツを利用します。上の図では、(PX,PY)=(0,0) を指定した場合に SZ=1 なら赤枠で囲まれた部分が使われることになります。そして、(1,15) のように、はみ出すような指定をすると、Pattern Set の内部で下から上に循環して、青枠のような使われ方をします。
SZ=2 (16x64), SZ=3 (16x128) は、それぞれ4つ、8つ使われることになります。
　パターンジェネレーターテーブルの先頭アドレスを指定する R#6 ですが、 Pattern Set#0 の先頭アドレスを指定することが出来ます。0以外を指定すると、VRAM256KB をはみ出しますが、はみ出した分は、また 0番地に戻ってきて使われます。
　VRAMの全域を参照できるのに、R#6 は何のために存在するか？というと、Palette Set の定義をまるごとシフトさせることで、R#6を書き替えるだけで全スプライトを一気に形状変更できるのがポイントです。例えば、アニメパターンを4つ用意しておいて、Pattern Set#0～#3 に書いておけば、R#6 を4パターン順繰りにセットするだけで、全スプライトがアニメーションするようになります。BASICから制御しても、それなら軽いですよね。

## 強制 Graphic4 (SCREEN5) VDPコマンドモード

　R#45 にはFG4レジスタがマッピングされています。R#20 の ECOMビット=1 の場合にのみ 1 を書き込めます。
　FG4 = 1 になると、全ての VDPコマンドが「Graphic4 (SCREEN5)」で動作している想定の挙動に切り替わります。

| REGNO | bit7 | bit6 | bit5 | bit4 | bit3 | bit2 | bit1 | bit0 |
| ----- | ---- | ---- | ---- | ---- | ---- | ---- | ---- | ---- |
| R#20  | S16  | EVR  |`ECOM`| EPAL | SP3  | ILNS | SVNS | HS   |
| R#45  |`FG4` |`XHR` | MXD  | MXS  | DIY  | DIX  | E0   | MAJ  |


　この機能は、Sprite mode3のパターンジェネレーターテーブルを加工するのにVDPコマンドを使えるようにします。なぜなら、Sprite mode3のパターンジェネレーターテーブルがGraphic4 (SCREEN5) のビットマップグラフィック（背景）と同じフォーマットだからです。
　FG4もXHRも、コマンドの１回の実行の度に、使うか使わないかを選ぶ機能なので、R#45 に配置されています。
