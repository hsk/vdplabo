# sc2_field1

## 概要

`sc2_field1.asm` は、MSX SCREEN2 上で擬似3Dフィールド描画を行うための最初の実験です。

本研究では、スペースハリアーのような奥行きを持ったフィールド表現を SCREEN2 のパターン機能（PCG）を利用して実現することを目的としています。

この段階では、

- アミアミパターンの生成
- パターンネームテーブルの設定
- カラーテーブルの更新

を用いて、床にストライプ状の模様を表示することを目標としています。

---

## 目的

SCREEN2 は 8x8 ドット単位のパターンを画面に並べて表示します。

本研究ではピクセル単位で描画するのではなく、

- パターンテーブル
- パターンネームテーブル
- カラーテーブル

を利用して高速な背景描画を実現します。

多少ブロック状に見えても高速に動作することを優先しています。

## ビルドと実行

本プロジェクトでは Glass Assembler を使用して ROM イメージを生成します。

使用している Makefile は以下の通りです。

```make
sc%:
	java -jar glass-0.6.jar $@.asm rom/$@.rom
#	../../../../../msxemu/msx2_sdl/app rom/$@.rom
	openmsx -carta rom/$@.rom

clean:
	rm -rf rom/*.rom

t%:
	java -jar glass-0.6.jar sc$*.asm rom/sc$*.rom
	rom/sc$*.rom
```

`sc2_field1.asm` をビルドして実行するには以下を実行します。

```bash
make sc2_field1
```

このコマンドにより、

1. `glass-0.6.jar` を用いて `sc2_field1.asm` をアセンブル
2. `rom/sc2_field1.rom` を生成
3. openMSX を起動して ROM を実行

という手順が自動的に行われます。

初期の実験ではこの環境を利用して開発と動作確認を行いました。

## 表示方式

まずパターンジェネレータテーブルにアミアミ模様を登録します。

```text
10101010
01010101
10101010
01010101
```

このパターンを画面全体へ配置します。

実際の色はカラーテーブルによって決定されます。

---

## パターンネームテーブル

SCREEN2 のネームテーブルを利用して画面全体をパターンで埋めています。

各行ごとに異なるパターン番号を割り当てることで、後の実験で複数パターンを利用できる構造になっています。

---

## ストライプテーブル

本バージョンでは 20 個のストライプテーブルを持っています。

```text
stripe_table_1
stripe_table_2
...
stripe_table_20
```

それぞれ異なる視点高さで生成されたデータです。

各テーブルは 192 ライン分のストライプ番号を保持しています。

---

## 視点高さ

プレイヤーの高さは `player_y` で管理しています。

```text
player_y = 0
↓
stripe_table_1

player_y = 1
↓
stripe_table_2

...

player_y = 19
↓
stripe_table_20
```

カーソル上下によって視点高さを変更できます。

視点が高くなるほど地平線が遠くなり、ストライプの収束具合が変化します。

本バージョンでは、field4.pyで生成した 20 段階の視点テーブル（stripe_table_1 ～ stripe_table_20）を用いて、player_y の値によってそれらを切り替えることで視点制御を行っています。

後のバージョンでは、より滑らかな変化や補間処理を追加することを想定しています。

---

## 前進アニメーション

前進量は `player_z` で管理しています。

毎フレーム

```asm
ld hl, player_z
inc (hl)
```

を実行し、ストライプ番号へ加算しています。

```text
stripe番号
＋
player_z
↓
4で剰余
↓
色決定
```

これにより床が手前へ流れてくるようなアニメーションを実現しています。

---

## 色変換

ストライプテーブルに格納されている値は色そのものではありません。

```text
0～15
```

のストライプ番号です。

これを

```asm
stripe_color_table:
    db 33h,23h,22h,23h,00h
```

で実際の SCREEN2 カラーコードへ変換しています。

この構造により、

- 色変更
- アニメーション
- 色数拡張

を容易に行えます。

---

## 描画処理

毎フレーム、

1. VSYNC待ち
2. キー入力処理
3. ストライプテーブル選択
4. 色変換
5. カラーテーブル更新

を実行しています。

描画対象は SCREEN2 のカラーテーブルのみであり、パターンそのものは変更していません。

---

## 今後の課題

本バージョンは基礎実験段階であり、以下の改善を予定しています。

- 色段階の増加（sc2_field2 で対応予定）
- 高速転送
- 天井の分離
- 背景描画

最終的には、

```text
天井
空
床
```

の3層構造によるスペースハリアー風背景表現を目指します。
