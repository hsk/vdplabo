# sc2_field2

## 概要

`sc2_field2.asm` は、SCREEN2 上で擬似3Dフィールドを表示するための第二段階の実験です。

`sc2_field1` ではストライプ／視点変化が4段階の粗いレベルで離散化されていました。本バージョンではこれを16段階に拡張し、奥行き方向の変化をより細かく分割することで、前進時のカクつきを軽減し滑らかな移動感を実現します。具体的には、stripe番号やz加算後の値を4bitスケール（0～15）で扱い、カラーテーブル参照の解像度を向上させています。

## カラーテーブル転送の変更（4段階→16段階化の詳細）

本バージョンでは、奥行き表現の精度を4段階から16段階へ拡張しています。

sc2_field1ではストライプ値および奥行き値を粗く4段階（実質2bit）で扱っていましたが、本バージョンではZ方向の計算を4bit（0〜15）スケールへ拡張し、より細かい前進変化を表現できるようにしています。

これにより player_z による前進量とストライプ値を合成した後も、0〜15の範囲で安定して扱えるようになり、カクつきの少ない距離変化が可能になります。

ただし、最終的な色選択は既存のカラーパレット構造を維持するため、一度4段階へ再圧縮して参照しています。

そのため以下のような変換フローになっています。

```asm
ld a,(hl)
cp ZSTEP
jr z, skip
    ld c, a
    ld a, (player_z)
    add a, c
    and ZSTEP-1
skip:
    sra a
    sra a
    ld hl, stripe_color_table
    ld c, a
    ld b, 0
    add hl, bc
    ld a, (hl)
    call WRTVRM
```

### 変換の意味

- 0〜15（4bit）: 奥行き＋ストライプ合成結果
- `and ZSTEP-1`: 16段階に制限
- `sra a` ×2: 4段階へ圧縮（既存カラーテーブル互換維持）

### 設計意図

この方式により、内部的には高精度（16段階）で奥行きを保持しつつ、最終的な色解像度は既存の4色構造を維持しています。

将来的にはこの4段階圧縮を廃止し、16段階そのままのカラーテーブルへ拡張することで、より滑らかなグラデーション表現へ移行することを想定しています。

## 課題

本バージョンでは遠近法表現は実現できていますが、高速化はしていないので

- 高速化
- 中間テーブル生成

などを導入して改善を行います。
