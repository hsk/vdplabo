# sc2_field7 ネームテーブルだけで天井と空と地面を描画する

ネームテーブル側だけを変更して天井と空と地面を描画します。

## カラーテーブル側

sc2_field6 をベースに、天井・空・地面を表現できるようにします。

今回の目的は天井あり空ありの描画を成立させることであり、高速化は目的としません。

## ネームテーブル側

sc2_field6 と同じ処理を使用します。

ただし、WRTVRM は大量のネームテーブル更新には遅いため、まず VDP を直接操作する実装を作成しました。

### 高速化

sc2_field7_1.asm は WRTVRM を VDP 直接アクセスへ置き換えたものです。

sc2_field7_2.asm はさらに不要な処理を削減し、ネームテーブル描画を高速化したものです。
具体的には、1行ごとに VDP の VRAM アドレスを設定し直す処理を見直し、VDP が持つ自動アドレスインクリメント機能を利用できるようにしました。
また、アドレス管理のためだけに行っていた不要なレジスタ更新やループ処理を削減し、より少ない命令数で同じネームテーブルを書き込めるようにしています。
描画結果は sc2_field7_1.asm と同じですが、より高速にネームテーブルを生成できることを目標としています。

### 空なし

天井  4行
地面 20行

これはsc2_field4と全く同じ処理をするだけです。

高速ステージ中の処理はこれです。

### 天井なし

空    5行
地面 19行

これはsc2_field6と全く同じ処理をするだけです。

通常ステージはこの処理を使います。

### 天井あり空あり

天井  4行
空    3行
地面 17行

これが今回新規に作るものになります。

高速ステージの導入部と終了部に使います。

カラーテーブル側で天井・空・地面の構成を表現します。

空なしや天井なしも含めて共通化できました。

### 天井あり空あり描画の詳細

空の描画は基本的に地面の描画と同じ処理を使用します。
違いは描画開始位置と描画行数です。

まず、天井の位置を表す変数として `ceil_y` を使用します。

高速ステージの導入時は ceil_y は 24 のような大きな値になっており、天井は存在しません。
その後 ceil_y が徐々に減少します。
ceil_y が player_y より大きい間は天井は表示されません。
ceil_y が player_y より小さくなると、画面上部から天井が現れ始めます。
さらに ceil_y が減少して 0 になると、地平線まで天井で覆われます。

高速ステージ終了時は逆に ceil_y が増加し、天井が徐々に消えて通常ステージへ戻ります。

`sky_height` は `player_y` と `ceil_y` の小さい方を用います。

```text
sky_height = min(player_y, ceil_y)
```

天井の高さは `sky_height` から求めます。

```text
ceil_height = player_y - sky_height
```

このため常に

```text
ceil_height + sky_height = player_y
```

が成立します。

例えば、

```text
player_y   = 7
sky_height = 4
```

の場合は、

```text
ceil_height = 3
```

となります。

転送元のアドレスは、`player_y - ceil_height` のところからになります。

描画構造は次のようになります。

```text
天井  4行
空    3行
地面 17行
```

空の描画開始位置は `ceil_height` 行目で、空の描画行数は従来のように `player_y` 行ではなく、`sky_height` 行になります。

地面の描画は従来通りです。
地面の開始位置は `player_y` 行目となり、描画行数もこれまでと同じです。

```text
天井
↓ ceil_height
空
↓ player_y
地面
```

この構造により、天井・空・地面を独立して制御できるようになります。
