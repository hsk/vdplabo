# v9918

TMS9918A互換のV9918について、[ルートREADME](../README.md)の「研究の進め方」に沿って stage1〜4 まで段階的に実装した研究ディレクトリ。他チップ(v9938以降)に先行して最も進んでいる。

| ステージ | 概要 | 状態 |
| --- | --- | --- |
| [stage1](stage1) | 適当に機能ごとに作ってみる(レジスタ・VRAM構成なし) | 完了 |
| [stage2](stage2) | ラスタライズを意識する(ラインごとの描画・表示制限) | 完了(v9918分。ドキュメントは未整備) |
| [stage3](stage3) | VRAMのアドレスを確定させる | スプライトのみ着手 |
| [stage4](stage4) | レジスタを確定させる | スプライトのみ着手 |

## stage1 — 適当に機能ごとに作ってみる

レジスタは使わず、VRAMの構成も考えずに、グラフィックス/テキスト/スプライトの各モードを個別のPythonスクリプトとして一気に描画する基礎実装。当たり判定や表示制限もしない。

- `v9918_graphics1.py` / `v9918_graphics2.py` / `v9918_graphicsmc.py` — グラフィックスモード1/2/マルチカラー
- `v9918_text1.py` — テキストモード
- `v9918_sprite1.py` / `v9918.py` / `v9918sp.py` — スプライト描画
- 各実装に対応する `docs/` 以下のドキュメントも完備

## stage2 — ラスタライズを意識する

ラインごとに描画するようになり、ラスタごとの表示制限もつけられるようにした。乗算をできるだけ避け加算のみで動くように各モードの描画を修正している。グラフィックス/テキストモードは素直に実装できたが、スプライト機能(1ラインあたりの表示枚数制限など)が難しいことが分かった段階。

- stage1と同様の各モードをライン単位描画に書き換え(`v9918_sprite1-1.py`/`v9918_sprite1-2.py`という中間版も残っている)
- ドキュメント(`docs/`)の整備はこのステージではまだ追いついていない

## stage3 — VRAMのアドレスを確定させる

スプライトのみ着手。stage1/2ではオブジェクトの属性をPythonの変数として直接保持していたが、ここからはスプライトアトリビュートテーブル(SAT)・スプライトジェネレータテーブル(SGT)をVRAM上のバイト列として扱い、アドレスも可変にする。

- SAT/SGTのVRAM参照化(アドレス可変)、8x8/16x16スプライト・2倍拡大
- 1ライン4枚制限、Y=208終端、Early Clock(EC/X-32)、color 0 transparent
- 5th Sprite(5S)フラグ、衝突(collision)判定
- 実ROM/BIOS互換のVRAMレイアウトに近づけている

グラフィックス/テキストモードのVRAM化は未着手。

## stage4 — レジスタを確定させる

スプライトのみ着手。コントロールレジスタ(`reg[0..7]`)とステータスレジスタ(`stat[0]`)を導入し、実機のI/Oポート越しの制御に近い形でVDPを操作できるようにした。パターンテーブル/アトリビュートテーブルのアドレスもレジスタ経由で設定する。

- レジスタ経由でのテーブルアドレス設定、ステータスレジスタ経由での5S/collision読み出し
- stage3までのスプライト描画機能(拡大、Y=208終端、EC、color0透過、1ライン4枚制限、5S、collision)をレジスタ駆動で再現
- `docs/README.md` にコントロールレジスタ(R#0〜R#7)・ステータスレジスタ(S#0)の仕様一覧あり

未着手: グラフィックス/テキストモードのレジスタ駆動化、モードレジスタ(M1/M2など)による画面モード切り替え。
