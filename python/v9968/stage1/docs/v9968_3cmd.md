はじめに

　今回は、V9968 に追加した VDPコマンドについて説明したいと思います。
追加したコマンド

　V9958 の VDPコマンドの番号は 4bit あり、16通り作れるはずなのですが、3つほど未使用の空きがあります。せっかくなので、この３つに新しいコマンドを増設してみました。追加したコマンドを下記の表にまとめます。
画像
新VDPコマンド一覧

　これらのコマンドは、互換性重視のために起動時には無効になっています。有効にするためには、R#20 の ECOMビットを 1 にする必要があります。
画像
R#20のビットマップ

　ECOMビットは、Extended VDP command mode の指定レジスタで、0 でV9958互換モード、1 で新VDP command 有効の拡張VDPコマンドモードになります。
LRMM

　Logical Rotate vraM to vraM です。V9958 の他のコマンドの名前に習って命名しています。
　このコマンドは、回転拡大縮小を実現するコマンドです。少し癖のある設定値にはなりますが、その設定値さえ頑張って作れば、ハードウェアによる回転拡大縮小の描画処理が使える、というコマンドになります。
　こんな動きをします。この動画は、page1 (裏画面) の画像をちょっとずつ回転させて page0 (表示画面) へ描画しています。画面の外側にはみ出した部分は画像が無くなるので、動画では水色になっています。

　設定値は、下記のようになります。
画像
LRMMの設定値

　(WSX, WSY), (WEX, WEY) は、転送元参照領域のウィンドウで、このウィンドウの外側を参照すると、転送元の画素の代わりに R#44 で指定した色が使われます。転送先とのロジカルオペレーションを実行後、転送先に描画されます。
　何かのキャラクターを回転させたい場合、その中心に回転中心を置きますが、(SX,SY) はあくまで参照の開始点なので、中心そのものを指定するわけではないのでご注意ください。この辺りの計算が必要になってきます。
　VX, VY は、小数部 8bit を持った固定小数点数です。なので回転させたい場合は、
　VX = INT( 256・COSθ )
　VY = INT( 256・SINθ )
を指定してください。256 が 1.0 相当で、数値を大きくすると縮小。小さくすると拡大になります。
LFMC

　Logical draw Font Cpu to vraM です。V9958 のVDPコマンドニーモニックは、転送先を先に書くルールで、名前の方は to を使って転送先を後に書くルールのようです。不思議なネーミングルールですが、今覆しても意味が無いので、そのルールを継承しています。
　このコマンドは、フォントデータを CPU から描画するコマンドです。LMMC はドット単位で書き込みますが、このコマンドは 8ドット単位で書き込むため、処理が軽くなっています。その代わり、２値画像しか描画できません。
画像
LFMCの設定値

　コマンド実行前に前景色は R#44 に、背景色は R#12 に指定します。コマンド実行後、水平 8ドット = 1byte で、順番に R#44 に書き込んで行きます。S#2 の TR bit が 1 になるのを待ってから書き込む手順です。
　NX が 8の倍数で無い場合は、その端数だけで 1byte を MSB側から消費していきます。残った bit は捨てられます。
　DIX, DIY がともに 0 であれば、下記のような走査順になります。

LFMM

　Logical draw Font vraM to vraM です。
　このコマンドは、VRAMに置かれているフォントデータを読み取って描画するコマンドです。8 x NY のフォントを 1文字とし、これを NX文字描画することになります。設定値は下記のようになります。
画像
LFMMの設定値

　SX, SY は、座標では無くアドレス指定として使います。R#32, #33 , #34 の 3byte に、256KB のどのアドレスにあるフォントデータを描画するかをリトルエンディアンで指定します。18bit のアドレスを A17…A0 とすると、A7～A0 を R#32、A15～A8 を R#33、A17～A16 を R#34 に指定します。R#35 は使いませんが 0 にしておきます。
　8 x NY の１文字単位で描画していきます。図では A,B,C,D,E と書かれている文字単位になります。そのため、下記のような変則的な走査順序になります。
　NX は、8 x NY を1文字とした、文字数を指定します。下図の例だと NX=5 ですね。
　漢字ROM の全角文字であれば、NY=16, NX=2 固定で、1文字単位で SX,SY にアドレスを指定して LFMM を実行するかたちになります。

まとめ

　もっと使いやすい、もっと面白い機能なども頑張れば作れるわけですが、V9968 の追加コマンドはあくまでオマケで入れました。本格的な機能追加は V9978 の方に譲ります。FPGA内の乗算器リソースが限られている（足りないと、汎用のロジックセルを大量消費して実現するようになるので無駄遣いできない）ので、V9968 の追加コマンドは簡単な加減算で実現できるもので、それなりに便利に使えそうなコマンドを３つほど搭載しました。
　私が思いつかないような使い方で、面白い表現を実現してくれる方が現れると良いなぁと思います。
